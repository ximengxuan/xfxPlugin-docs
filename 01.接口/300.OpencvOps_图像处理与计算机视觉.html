OpencvOps_图像处理与计算机视觉 ​

模块简介 ​

OpencvOps 封装了 OpenCV Mobile 5.0.0 的 C++ 图像处理与计算机视觉能力，通过单一 JNI 入口 + 命令分发架构暴露给懒人精灵(Lua) 调用。新增 OpenCV 能力时无需逐个声明接口，只需在 C++ 分发器中增加命令分支即可。

架构与设计原则 ​

懒人精灵(Lua)
   │  OpencvOps.process(bitmap, command, paramsJson)
   ▼
Kotlin OpencvOps.kt（单入口，命令转发）
   │  nativeProcess()
   ▼
C++ opencv_jni.cpp（命令分发器）
   │  Bitmap <-> cv::Mat 转换 | MAT 缓存池
   ▼
OpenCV Mobile 5.0.0（静态库，全 ABI）

核心特性：

  • 命令驱动：command + 参数JSON 调用，避免为每个 OpenCV 函数编写 JNI 声明
  • MAT 缓存池：中间结果用句柄复用，避免反复 JNI 传输大图
  • Bitmap 直传：输入截图直接传 Bitmap，native 层零拷贝转换
  • 统一返回：所有命令返回 {"code":0,"message":"ok",...} 结构
  • 全架构：arm64-v8a / armeabi-v7a / x86 / x86_64 均已编译

通用约定 ​

返回格式 ​

成功：{"code":0,"message":"ok", ...业务字段} 失败：{"code":非0,"message":"错误说明"}

错误码表 ​

code含义
0成功
1001参数错误（command/path/mat 缺失等）
2001未知命令
2002Mat 句柄不存在
3001图像解码失败（Bitmap 转 Mat / imread 失败）
3002图像编码失败（imwrite 失败）
4001操作执行失败

输入方式 ​

方式说明
bitmap直接传 Bitmap（截图），native 层自动转 cv::Mat
mat 句柄传 {"mat":"mat_1"}，从缓存池取 Mat（适合复用中间结果）

Mat 句柄生命周期 ​

  • 图像处理结果默认返回 Mat 句柄（如 mat_1）
  • 务必在不再使用后调用 releaseMat(matId) 释放 native 内存
  • 批量处理可调用 clearMats() 一次性清空
  • 需要将 Mat 转回 Bitmap 时调用 matToBitmap(matId)

API 接口列表 ​

读取与保存 ​

方法返回说明
imread(path)String读取图片文件为 Mat 句柄
imwrite(matId, path)String将 Mat 句柄保存到文件

Mat 池管理 ​

方法返回说明
storeMat(bitmap)String将 Bitmap 存入 Mat 池，返回句柄
releaseMat(matId)String释放 Mat 句柄
matInfo(matId)String查询 Mat 尺寸/通道/类型
clearMats()String清空 Mat 池
matToBitmap(matId)Bitmap将 Mat 句柄转回 Bitmap

核心图像处理 ​

各命令第二个参数 matId：传非空 Mat 句柄时优先使用 Mat 池中的图（性能更优）；传 nil 则使用第一个参数 bitmap。

性能优化策略 ​

1. 减少 JNI 往返 ​

  • 用 Mat 句柄复用中间结果，避免每次调用都重传 Bitmap
    lua
    local store = OpencvOps.storeMat(bitmap)            -- 一次性转 Mat
local gray = OpencvOps.cvtColor(nil, store.mat, "BGR2GRAY")  -- 用 mat 句柄
local th = OpencvOps.threshold(nil, gray.mat, "binary", 127)
-- ... 使用 th.mat ...
OpencvOps.releaseMat(gray.mat)
OpencvOps.releaseMat(th.mat)

2. 缩小处理范围 ​

  • 处理前先 resize 缩小到目标检测所需最小分辨率
  • 用 ROI 裁剪只处理感兴趣区域

3. 合理选择算法 ​

场景推荐
UI 元素定位matchTemplate（ccoeff_normed）
大面积找图先 resize 缩小再匹配
边缘提取canny 前先 blur 降噪
颜色过滤cvtColor(BGR2HSV) + 阈值

4. 多线程并发 ​

  • JNI 入口使用 synchronized 保证线程安全（同进程单实例）
  • 高并发场景建议在 Lua 侧用协程/队列串行化处理，避免阻塞主线程
  • 大图处理可在脚本层放到后台线程

防御性编程建议：

  1. 每次调用都检查 code == 0

  3. findContours 检查 count > 0 再遍历
  4. 文件操作（imread/imwrite）先确认路径可读写

内存管理方案 ​

native 层（已内置） ​

  • MAT 缓存池：所有中间 Mat 缓存在 native 池，用句柄访问
  • 自动释放：命令内部创建的临时 Mat 在返回前自动释放
  • 线程安全：池操作用 std::mutex 保护

Kotlin/Lua 层（需遵守） ​

  1. 用完即释放：storeMat / 各命令返回的 Mat 句柄，用完调用 releaseMat
  2. 批量清理：脚本结束时调用 clearMats() 释放全部
  3. Bitmap 回收：matToBitmap 返回的 Bitmap 用 ImageOps.recycle() 回收
  4. 避免泄漏：循环处理时，每轮迭代产生的 Mat 及时释放
lua
-- 循环处理示例（注意每轮释放）
for i = 1, 10 do
    local gray = OpencvOps.cvtColor(bitmap, nil, "BGR2GRAY")
    local th = OpencvOps.threshold(nil, gray.mat, "binary", 127)
    -- ... 处理 th.mat ...
    OpencvOps.releaseMat(gray.mat)
    OpencvOps.releaseMat(th.mat)
end
OpencvOps.clearMats()

跨平台兼容性 ​

  • 全 ABI 支持：arm64-v8a / armeabi-v7a / x86 / x86_64
  • 静态库集成：OpenCV 编译进 libxfx_yolo.so，无额外 so 依赖
  • 系统要求：Android 7.0+（API 21），opencv-mobile 要求 C++17
  • 打包架构：由 app/build.gradle.kts 的 abiFilters 决定，当前默认 arm64-v8a + x86_64
