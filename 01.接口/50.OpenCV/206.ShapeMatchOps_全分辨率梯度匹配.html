ShapeMatchOps（已废弃） ​

模块简介 ​

废弃说明

⚠️ 改类已经废弃。 核心接口和功能已迁移到 OpencvOps。暂时存档。

ShapeMatchOps 提供 xfxYolo PC 端训练出的 OpenCV 风格 YAML 模板匹配能力，适合在安卓脚本中识别透明形状、按钮、图标等目标。

模板可直接从 YAML 路径匹配，也可以先用 loadYaml(yamlDirOrFile) 预加载到 native 内存，再通过 YAML 名称匹配 Bitmap、图片路径或 OpencvOps 的 Mat 池句柄。

功能概览 ​

  • 读取一个或多个 PC 端训练出的 .yaml / .yml
  • 支持 Bitmap、图片文件路径、OpencvOps Mat 池句柄作为输入
  • 支持全分辨率 shape_full_points / shape_full_features
  • 支持多 YAML、同 label 多模板、统一 NMS、单目标 max_instances
  • 支持与 PC 端多边形检测工具同步的 OpenCV 轮廓检测，用于查找矩形头像框、网格卡片等四边形目标
  • 返回 JSON 字符串，便于懒人精灵和 Lua 解析

YAML 名称规则 ​

yamlNames 用于引用已经通过 loadYaml 加载到内存的模板，兼容以下写法：

写法示例
单个名称"方向轮盘"
JSON 数组字符串'["方向轮盘","盾牌"]'
竖线分隔`"方向轮盘
带后缀"方向轮盘.yaml" / "盾牌.yml"

带 .yaml / .yml 后缀时会自动去掉后缀后再查找内存中的 label。

直接匹配接口 ​

直接传入 YAML 文件路径并匹配，不需要提前调用 loadYaml。适合一次性匹配或脚本侧不想维护预加载状态的场景。

bitmapBitmapBitmap 接口必填待匹配 Bitmap，不能为 null 或已回收

matchMat ​

使用 OpencvOps Mat 池中的图片执行预加载 YAML 匹配。matId 是 OpencvOps.bitmapToMat、readResMat、crop 等接口返回的 Mat 句柄，不是 Mat 对象本身。

该接口会先按 matId 从 Mat 池取图，再转换为 Bitmap 交给现有 native Bitmap 匹配入口处理。当前 native 层只有 Bitmap 形状匹配 JNI，没有 Mat 地址直通入口，因此在不改 native 的前提下，这是只改 Kotlin 层能落地的兼容实现；它避免了 Lua 侧手动 matToBitmap 和额外资源管理。

参数名类型必填说明
matIdString是Mat 池句柄，如 mat_1
yamlNamesString是已预加载 YAML 名称，支持单名、JSON 数组、竖线分隔、带 .yaml/.yml 后缀
x1Int是搜索区域左上角 x 坐标
y1Int是搜索区域左上角 y 坐标
x2Int是搜索区域右下角 x 坐标；传 0 表示由 native 使用整图边界
y2Int是搜索区域右下角 y 坐标；传 0 表示由 native 使用整图边界
thresholdFloat是分数阈值，范围 0.0 到 1.0
countInt是每个 YAML/模板最多保留的候选数量，小于 1 时按 1 处理
pyramidModeString是金字塔模式，传空字符串或 null 时默认 "4,8"
nmsFloat是NMS 阈值，范围 0.0 到 1.0

返回值为 JSON 字符串。成功时 code 为 0，matches 为匹配结果数组；matId 为空、Mat 池不存在该句柄、阈值非法或 Mat 转 Bitmap 失败时返回错误 JSON。

多边形检测接口 ​

detectPolygonsImageFile / detectPolygonsBitmap ​

多边形检测主要用于查找矩形头像框、卡片边框、网格区域等轮廓目标。

参数名类型必填说明
imagePathString图片路径接口必填待检测图片路径
bitmapBitmapBitmap 接口必填待检测截图 Bitmap，不能为 null 或已回收
edgeCountInt是目标角数/边数，矩形传 4
compareModeInt是边数比较方式：0 等于、1 大于等于、2 小于等于
retrievalModeInt是搜索模式：0 RETR_EXTERNAL、1 RETR_LIST、2 RETR_CCOMP、3 RETR_TREE
approxModeInt是轮廓近似方法：1 CHAIN_APPROX_NONE、2 CHAIN_APPROX_SIMPLE、3 TC89_L1、4 TC89_KCOS
minAreaFloat是最小面积，-1 表示不限制
maxAreaFloat是最大面积，-1 表示不限制
approxEpsilonFloat是近似逼近阈值，-1 表示自动
scoreThresholdFloat是得分阈值，保留 similarity >= scoreThreshold 的结果；传 -1 表示不过滤

先对灰度图执行 Canny 作为主轮廓，再从 HSV 饱和度/亮度和 BGR 通道生成增强边缘图，叠加 Sobel+Otsu 梯度掩膜、形态学闭合和膨胀后查找轮廓。每个轮廓按 minArea / maxArea 过滤，用 approxPolyDP 得到边数，并按 compareMode 判断是否匹配。

返回值为 JSON 字符串。成功时 code 为 0，matches 为多边形结果数组。

Steam 账号切换：检测矩形头像框 ​

lua
import('com.nx.assist.lua.LuaEngine')

local xfxModule = require('lib/XfxPlugin')
local XFX = xfxModule:new({
    apkName = 'xfxPlugin-release.apk',
    context = LuaEngine.getContext(),
})

local shapeOps = XFX:getOps('shapeMatchOps'); assert(shapeOps)
local opencvOps = XFX:getOps('opencvOps'); assert(opencvOps)

local imagePath = '/sdcard/Download/opencvTest/测试大图/截图_1785809395573.png'

local function rectJson(list)
  local arr = {}
  for i = 1, #list do
    local r = list[i]
    arr[#arr + 1] = string.format('[%d,%d,%d,%d]', r.left, r.top, r.right, r.bottom)
  end
  return '[' .. table.concat(arr, ',') .. ']'
end

local result = shapeOps.detectPolygonsImageFile(imagePath, 4, 0, 0, 2, 8000, -1, -1, 0.5)
printEx(result)

local obj = jsonLib.decode(result)
if obj.code == 0 then
  local avatarRects = {}
  for i, item in ipairs(obj.matches) do
    if item.left < 220 and item.top > 1600 and item.edgeCount == 4 then
      printEx('矩形 center=(' .. item.centerX .. ',' .. item.centerY .. ') area=' .. item.area)
      avatarRects[#avatarRects + 1] = item
    end
  end

  if #avatarRects > 0 then
    local img = opencvOps.readResMat(imagePath)
    local boxed = opencvOps.drawRects(img, rectJson(avatarRects), '#53EAFD', 4, false, true)
    opencvOps.saveMat(boxed, '/sdcard/Download/opencvTest/矩形检测结果.png')
    opencvOps.clearMats()
  end
else
  printEx(obj.message)
end

注意事项 ​

  • 推荐高频场景先调用 loadYaml(yamlDirOrFile)，再使用 matchMat 或预加载版匹配接口。
  • loadYaml 现在只有一个参数；旧的 loadYaml(names, yamlDirOrFile) 调用需要改为 loadYaml(yamlDirOrFile)。
  • releaseYaml('') 和 releaseYaml(nil) 都会释放 native 内存中的全部 YAML。
  • matchMat 的 matId 必须来自 OpencvOps Mat 池。句柄无效或已 recycle 后会返回 1001。
  • 当前 native 层提供 Bitmap 匹配 JNI，matchMat 在 Kotlin 层从 Mat 池取图并转换后调用 native 匹配；如需完全跳过 Bitmap 转换，需要后续新增 native Mat 地址入口。
  • 需要全目录直接识别时，优先使用 matchImageFileFromYamlDir 或 matchBitmapFromYamlDir，可减少脚本侧枚举和 JNI 往返。
  • 当前安卓端复用轻量 native 匹配实现，已同步 metadata、全分辨率 shape 点、edge 粗筛、orientation 复核和 page exclusive 语义；与 PC 端 OpenCV/Numpy 的 matchTemplate 细节仍不完全逐像素一致。
  • 为获得更稳定性能，建议在 YAML metadata 中显式写入 search_region、max_instances、min_edge_score、min_orientation_score 和必要的 negative_regions。
