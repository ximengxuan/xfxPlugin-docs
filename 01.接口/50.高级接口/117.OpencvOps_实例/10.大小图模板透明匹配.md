# 大小图模板透明匹配

## 大小图模板透明匹配

演示如何用 `OpencvOps` 接口实现"在大图采样,在小图目标区域匹配"。

* **核心接口（3 个）**：`readResMat` / `cropMat` / `findImg`
* **缩放基础方法（1 个）**：`resizeMat` —— 把大图模板缩放到小图标实际大小
* **画框标记（可选）**：`drawRect` / `saveMat`

## 背景

游戏场景：

* 采样图（1280x720）显示一个 **"选择陷阱"的 UI**，每个陷阱单元格约 190x155 像素。
* 测试图（1280x720）显示**实际游戏画面**，底部工具栏每个陷阱是**小图标**约 60x32 像素。
* 小图标背景**半透明**叠加在游戏场景之上，存在游戏画面的颜色干扰。
* 但**陷阱主体**（如"净水大炮"的白色炮体）在两种显示下是一致的。

需求：在采样图上截取"净水大炮"的大图，作为模板；然后在测试图底部工具栏的 4 个格子里，**多尺度灰度模板匹配**找到该小图所在的位置。

## 算法思路（4 步）

> **核心**：因为模板和目标的**缩放比固定**（约 0.4 倍），所以算法很简单 —— 把模板转灰度后按 0.35~0.50 倍缩放到小图标实际大小，遍历这些尺度，在工具栏区域用 `findImg` 找匹配，取最高分。

1. **从采样图取模板**：用 `cropMat` 在采样图上截取"净水大炮"主体（约 150x80）
2. **转灰度 + 多尺度缩放**：用 `matToGray` 把大图和模板转灰度，用 `resizeMat` 把模板缩放到 0.35~0.50 倍（约 53~75 宽）
3. **底部工具栏多尺度匹配**：用 `findImg` 在测试图底部区域 (x=400~850, y=590~720) 搜索，取最高分
4. **取最佳匹配**：返回 `{score, left, top, right, bottom, width, height, centerX, centerY}`

> 灰度转换是必要的：`TM_CCOEFF_NORMED` 在灰度图上最稳定、最快，且能抗住"小图标半透明背景叠加游戏场景"的颜色干扰（半透明只改变颜色，不改变灰度结构边缘）。

## Lua 示例

> **多尺度匹配的循环封装在 Lua 调用侧**（`findMultiScale` 局部函数），避免新增专用底层方法。灰度转换 + 多尺度 + findImg 全部用通用基础接口组合。

```lua
-- 大小图模板匹配（Lua 侧封装多尺度，主流程简洁）
local UtilsMain = loader.loadClass('com.xfx.plugin.UtilsMain')
UtilsMain.init(LuaEngine.getContext())

-- -- 引入图像识别类
-- local opcvOps = XFX:getOps('opencvOps'); assert(opcvOps)
local opcvOps = UtilsMain.opencvOps()

local path = '/sdcard/Download/opencvTest/'

-- ========== 通用函数：多尺度灰度模板匹配 ==========
-- 参数：大图 matId、模板 matId、搜索区域、尺度范围、阈值
-- 内部：matToGray 转灰度 + resizeMat 缩放 + findImg 匹配，返回最佳结果或 nil
local function findMultiScale(imgMat, tplMat, x1, y1, x2, y2, minScale, maxScale, step, precision)
    local srcGray = opcvOps.matToGray(imgMat)   -- 转灰度
    local tplGray = opcvOps.matToGray(tplMat)
    local bestScore, bestMatch = -1, nil
    for scale = minScale, maxScale, step do
        local w = opcvOps.getWidth(tplGray) * scale  -- 缩放到当前尺度
        local curTpl = opcvOps.resizeMat(tplGray, w, 0, 1)
        local res = opcvOps.findImg(srcGray, curTpl, 1, precision, x1, y1, x2, y2)
        if res ~= "[]" then
            local m = jsonLib.decode(res)[1]
            if m.score > bestScore then
                bestScore, bestMatch = m.score, m
            end
        end

        opcvOps.recycle(curTpl)
    end

    opcvOps.recycle(srcGray)
    opcvOps.recycle(tplGray)

    return bestMatch
end

-- ========== 主流程 ==========
-- 1. 读取采样图（"选择陷阱"UI）
local sampleImg = opcvOps.readResMat("/sdcard/Download/插件实例/逆战未来/截图_1785835136206.png")
if sampleImg == "" then print("读取采样图失败"); return end

-- 2. 在采样图上截取"净水大炮"主体（避开文字/价格）
--    实际坐标根据采样图调整：x=130~280, y=180~260
local tplMat = opcvOps.cropMat(sampleImg, 130, 180, 280, 260)
opcvOps.saveMat(tplMat, path .. "/净水大炮_模板.png")  -- 可选：保存模板

-- 3. 读取测试图（在底部工具栏搜索）
local testImg = opcvOps.readResMat("/sdcard/Download/插件实例/逆战未来/截图_1785810461705.png")
if testImg == "" then print("读取测试图失败"); return end

-- 4. 多尺度灰度匹配（0.35~0.50 倍，步长 0.05，阈值 0.7）
local bestMatch = findMultiScale(testImg, tplMat, 400, 590, 850, 720, 0.35, 0.50, 0.05, 0.7)

-- 5. 输出结果
if bestMatch then
    print(string.format("找到净水大炮 score=%.3f 中心=(%d,%d) 大小=%dx%d",bestMatch.score, bestMatch.centerX, bestMatch.centerY, bestMatch.width, bestMatch.height))
    -- 画红框标记
    local boxed = opcvOps.drawRect(testImg, bestMatch.left, bestMatch.top,bestMatch.right, bestMatch.bottom, "#FF0000", 2, false, true)
    opcvOps.saveMat(boxed, path .. "/净水大炮.png")
else
    print("未找到净水大炮")
end

opcvOps.recycle(sampleImg)
opcvOps.recycle(tplMat)

-- 按需：销毁全部Mat资源
opcvOps.clearMats()
```

## 为什么不新增 findImgEx 多尺度接口？

**封装到 Lua 调用侧，而非 OpencvOps 底层**，原因：

1. **灰度转换、多尺度缩放都是通用基础能力**，应保持为独立基础接口（`matToGray` / `resizeMat` / `findImg`），由 Lua 侧自由组合。把它们捏合成一个 `findImgEx`，反而限制了灵活性。
2. **多尺度的尺度范围、步长、搜索区域、阈值都是业务参数**，因人因图而异。塞进底层接口会导致接口签名膨胀，且难以覆盖所有场景。
3. **符合"Lua 侧聚合、Java 侧基础"的分层原则**。OpencvOps 只暴露最细粒度的通用操作，业务聚合逻辑放 Lua 函数。这样其他场景（滑块、轮廓、投影）也能复用 `matToGray` + `resizeMat`。

## 说明

* `findImg` 内部使用 `TM_CCOEFF_NORMED` 归一化互相关匹配，**对整体亮度变化和轻微形变鲁棒**。
* 灰度匹配可以抗住"小图标半透明背景叠加游戏场景"的颜色干扰（半透明叠加只改变颜色，不改变结构性边缘）。
* 多尺度扫描（0.35~0.50）应对不同测试图分辨率或缩放偏差。
* `resizeMat(width, 0, 1)` 中 `width>0, height=0` 表示"宽 width、高按比例"。
* 若图片分辨率差异较大，可调整 `scale` 扫描范围和步长。
